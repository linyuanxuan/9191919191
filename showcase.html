01 / FEATURES

它做了什么

前端尽量薄，计数全部交给边缘；该兜底的地方都兜住。

◍

单文件前端

白底黑框，两个通道都指向同一个被骗页；hash 路由切换视图，不刷新、不跳转外部页面。

↻

后端全局计数

Workers KV 保存全局计数，POST /api/hit 加一，GET /api/count 只读；页面不使用 localStorage。

♪

自动播放兜底

先静音自动播放绕过浏览器限制，点击页面任意位置开启声音；接口超时与失败都有降级提示，不卡死页面。

⌘

CORS 与预检

OPTIONS 返回 204，所有响应（含错误）都带 CORS 头，并用 no-store 防止计数被缓存。

◈

简单 IP 限流

单 IP 每 60 秒最多 5 次 hit，KV 里只存 IP 哈希，超限返回 429 与 Retry-After。

✓

脏数据容错

KV 内容非纯数字、负数或溢出一律按 0 处理；KV 读写异常返回 503 而不是让请求崩掉。

02 / QUICKSTART

四步跑起来

从空仓库到能骗人，需要两次部署和两个占位符。

1

创建 KV 命名空间

npx wrangler login npx wrangler kv namespace create COUNTER_KV

把输出的 id 填进 wrangler.toml 的 id 字段。本地 dev 可再加 --preview 生成 preview_id。

2

部署 Worker

npx wrangler dev # 本地调试 npx wrangler deploy # 上线

部署成功后终端给出 https://rickroll-counter.<子域>.workers.dev，即 API 地址。

3

配置前端 API 地址

<html lang="zh-CN" data-api="https://rickroll-counter.<子域>.workers.dev">

临时测试可用查询参数覆盖：index.html?api=https://xxx.workers.dev。

4

托管前端

git add -A git commit -m "feat: 91 video Rickroll 计数器" git push -u origin main

纯静态单文件，GitHub Pages 或 Cloudflare Pages 直接托管，无需构建。

04 / LIMITS

先说清楚它做不到什么

整活项目也要把边界写明白。

✕

计数不是严格原子
Workers KV 最终一致且没有原子自增，并发写入可能少量漏计。需要精确计数请换 Durable Objects。

✕

限流不是安全边界
同样受 KV 最终一致影响，属于尽力而为的防刷；要硬限流请用平台 Rate Limiting API 或 Durable Objects。

✕

YouTube 可能被网络环境拦截
页面会降级为普通 iframe 并给出跳转链接；降级模式下「点击开声音」靠重建播放器实现，成功率不是 100%。

✕

两个占位符必须替换
wrangler.toml 的 KV id 与 index.html 的 data-api 默认是占位值，不替换无法正常运行。
